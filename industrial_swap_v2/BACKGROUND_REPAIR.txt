方法
1. inspect_background_repair.py 读取原背景、M1 坐标系及 LangSplat 地面分数。
   对底座可见贡献反传背景透明度，定位造成遮挡的高斯；另对局部暗像素
   反传颜色，定位不透明黑色残影。两种归因均来自实际三维高斯渲染。
2. repair_background.py 联合检查三维位置、协方差支持范围、方向、尺度、
   地面语义及渲染贡献，先删除异常高斯。大高斯即使中心在旧删除框外，
   仍可能覆盖框内，这正是仅按中心删除不能处理的一部分残影。
3. 从 220 个可靠周边地面高斯拟合局部地面，使用 1850 个经深度、颜色和
   语义检查的周边地面颜色样本补全三维地表。补丁是有位置、旋转、尺度、
   不透明度和 SH 参数的真正三维高斯，不是改渲染图。
4. 原机械臂底部低于周围拟合平面，因此新补面在底座附近与其既有支撑高度
   衔接，并过渡到周边地面。仅补面具有这个局部高度变化，机械臂完全不动。
   补面外沿低于保留的薄地面和标线高斯，以免覆盖原标线。
5. 与原 object_world.ply 合成，独立重新读取交付 PLY 渲染，并导出对比。

复现（远端项目根目录，需保留项目现有 M1/M2/M3 数据与 GSLE 环境）
SWAP_GPU=1 bash industrial_swap_v2/run_background_repair.sh
可用第一个参数指定来源 config.yaml，第二个参数指定新的输出 run 名。
脚本检查可用显存，所有输出进入新目录，目录已存在时拒绝覆盖。
步骤为 inspect_background_repair -> repair_background -> export_background_repair。
运行时 GPU 为共享资源，应选择空闲显存足够的卡；本次使用 GPU 1。

模块输入输出
inspect_background_repair --config CONFIG --output NEW_INSPECTION
  输入：CONFIG 指向的 M1/M2/M3、现有地面语义分数。
  输出：attributes.npz、dark_attribution.npz、统计 JSON 及归因渲染。
repair_background --config CONFIG --inspection INSPECTION --output NEW_REPAIR
  输入：归因结果、既有背景和机械臂。
  输出：清理索引、三维地面、修复背景、scene_coarse_fixed.ply 及同视角图片。
export_background_repair --config CONFIG --repair REPAIR
  输入：修复结果。
  输出：validation/ 下的独立校验、13 视角图像、两段视频及相机记录。
show_background_repair --preview-dir LOCAL_PREVIEW
  输入：下载的实际渲染和 repair_report.json。
  输出：带文字、同区域放大对照的 same_view_comparison.png；不改原始渲染内容。
